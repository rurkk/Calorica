# Ожидание холодного старта сервера

Ветка: `codex/server-warmup`; отдельная доработка после принятой доставки T01.
Android-основа T02 уже интегрирована; владелец подтвердил, что app-файлы свободны.
Assets и метаданные выпуска T02 не меняются; его self-check сохраняется отдельно.

- AC-1: при первом открытии приложение проверяет readiness до 90 секунд;
  обычные HTTP-запросы сохраняют таймаут 10 секунд.
- AC-2: только JSON `status=UP` разрешает переход к экранам приложения.
  Сетевой сбой, таймаут, DOWN и временная страница Render допускают повтор GET.
- AC-3: ожидание показывает состояние, имеет конечный срок и кнопку повтора
  после ошибки; двойной тап не создаёт параллельных проверок.
- AC-4: уход в фон отменяет незавершённое ожидание. Новый foreground может
  начать его снова; успешная проверка сохраняется в памяти Activity ViewModel.
  Постоянного фонового polling и повторов операций записи нет.
- AC-5: deploy-script после Live проверяет публичный readiness до 90 секунд,
  не передаёт ему административный ключ и не сохраняет неготовый digest.

Проверки: виртуальное время и отмена для Android, MockWebServer для реальных
ответов, тесты deploy-script, полный Android unit/debug/release gate и CI.
UI проверяется деревом UIAutomator без скриншотов. Существующие чужие задачи,
ключ подписи и пользовательские данные сохраняются.
