# Домен продуктов и питания

Используем Kotlin/Spring Boot, Spring JDBC с явным SQL, PostgreSQL, Liquibase,
единый репозиторий и существующий Kotlin/Compose-каркас. Сервер хранит данные и выполняет расчёты;
Android отвечает за ввод, запросы и представление.

## Обязательная серверная реализация

| Область | Правила реализации | Источник точных правил |
| --- | --- | --- |
| Продукты | Единая сущность; базовые и личные; тип определяется наличием компонентов; ручные КБЖУ сохраняются при превращении в состав | [Граф](../requirements/domain/product-composition-graph.md) |
| Граф | Вложенность и общие ингредиенты, отсутствие циклов, проверка владельца, исходные массовые доли, сумма 1 | [Граф](../requirements/domain/product-composition-graph.md) |
| Выход | Nullable-коэффициент связи и ручной коэффициент карточки; два взаимоисключающих режима, значения ниже/выше 1 | [Выход](../requirements/domain/cooking-yield.md) |
| Расчёты | Актуальные значения при запросе, рекурсивный SQL, каждый путь графа учитывается, никаких сохранённых итогов КБЖУ | [Принципы](../requirements/domain/calculation-principles.md) |
| Массы | Входные массы состава не сохраняются; хранятся доли/коэффициенты; обязательные съеденные граммы — только в дневнике | [Выход](../requirements/domain/cooking-yield.md) |
| Единицы | Справочник г/мл и конвертации конкретного продукта; без конвертации доступны только граммы; личные продукты изначально только в граммах | [Единицы](../requirements/domain/units-of-measurement.md) |
| Лейблы | Общие продуктовые и пищевые; несколько связей; родительские лейблы сохраняются, но игнорируются; удаление лейбла удаляет связи | [Лейблы](../requirements/domain/product-and-meal-labels.md) |
| Дневник | Ссылка на продукт и съеденные граммы, UTC-время и пищевые лейблы; без снимка КБЖУ и исходной единицы ввода | [Дневник](../requirements/functional/meal-diary.md) |
| Удаление | Оба режима мягкого удаления; каскад к зависимым родителям, не ингредиентам; история сохраняется; Admin не меняет чужие личные данные | [Доступ](../requirements/domain/access-and-soft-deletion.md) |
| Числа | NUMERIC/BigDecimal, точная нормализация долей, различие NULL и 1, отсутствие раннего экранного округления | [Точность](../architecture/numeric-precision.md) |
| Время | UTC-моменты, календарные границы по переданному IANA-поясу; неделя пн–вс, полный месяц, пустые дни включены в среднее | [Политики](../architecture/runtime-policies.md) |

Эта таблица не переопределяет формулы источников и не разрешает реализовать только DDL.

## Ключевые формулы для контроля

При наличии хотя бы одного заданного коэффициента связи:

```text
Y = sum(w_i * coalesce(k_i, 1))
q_i = w_i * coalesce(k_i, 1) / Y
manual_yield_factor = NULL
```

Если все коэффициенты связей отсутствуют:

```text
Y = coalesce(manual_yield_factor, 1)
q_i = w_i
```

В обоих случаях:

```text
KBJU_per_100g = sum(w_i * child_KBJU_per_100g) / Y
diary_KBJU = consumed_g / 100 * KBJU_per_100g
allocated_child_g = allocated_parent_g * q_i
```

Явная 1 на связи включает первый режим. Коэффициент связи не умножает КБЖУ
в числителе. Дочерние КБЖУ уже учитывают собственный выход ребёнка.
Распределение граммов по лейблам и расчёт нутриентов — разные вычисления.

## Транзакции и доступ

- Состав и выход сохраняются атомарно. Сервер проверяет права на каждую операцию.
- Для изменений графа используется транзакционная блокировка по владельцу,
  отдельный ключ для базового каталога, чтение после получения блокировки.
- Протокол гонок между владельцами при удалении базового ингредиента остаётся
  задачей проектирования перед реализацией. Нельзя заявлять, что блокировка одного
  владельца автоматически закрыла её. Нужны определённый порядок операций и тест.
- Предпросмотр каскада не заменяет повторной серверной проверки при выполнении.
  Список чужих личных зависимостей не раскрывается администратору.
- Ответ с несколькими расчётными запросами строится на согласованном снимке.
- Ограничения размера запроса, диапазонов NUMERIC и времени выполнения фиксируются
  в контракте до написания клиентов. Превышение возвращает ошибку, не частичный расчёт.
  Произвольное ограничение вложенности «одним блюдом» не допускается.

## Минимум инфраструктуры домена

Один серверный Gradle-модуль, пакеты по предметным областям, одна БД.
Один общий механизм расчётов для карточки, дневника и аналитического ответа.
Миграция содержит около 50 базовых продуктов и справочники;
источники данных указываются в комментариях миграции, не в интерфейсе.

Сессии реализуются по [существующей политике](../architecture/runtime-policies.md):
email/пароль, Argon2id, access/refresh, ротация, отзыв сессии и безопасное хранение
refresh token в Android.
