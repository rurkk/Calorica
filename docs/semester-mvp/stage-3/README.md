В ТЗ включены все прежние главы [второго этапа](../stage-2/README.md), функциональные
и нефункциональные требования, дополненные кратким архитектурным обзором.
Файлы прошлых лабораторных не изменяются. Все формулировки перенесены дословно,
кроме обновления основания документа и ранее согласованных эксплуатационных исключений.
Эти точечные изменения явно перечислены в сборщике и учтены при сверке.

В diagrams/ находятся семь исходников draw.io, в assets/ — их экспорты
с внедрённым XML. DOCX и PPTX содержат одинаковые изображения. Каждый блок
и связь редактируются в draw.io; текст и таблица презентации — в PowerPoint.

Используется одна PostgreSQL. Её модель разделена на два рисунка для читаемости:
аккаунты и каталог; дневник и метки. Всего 12 таблиц, каждая показана отдельным
блоком; каждое поле — отдельной строкой, ключи и ссылки указаны справа.
В ТЗ эти два рисунка размещены на отдельных альбомных страницах A4.
У схем нет внешних легенд и пояснений, у рисунков в Word нет подписей.
Протоколы и SYNC/ASYNC указаны на связях. Доклад добавлен в заметки PowerPoint.

## Сборка и проверка

[build_diagrams.py](build_diagrams.py) проверяет готовые XML и экспортирует их,
сохраняя ручную компоновку исходников:

```text
python -B build_diagrams.py
python -B build_diagrams.py --export
```

[build_data_diagrams.py](build_data_diagrams.py) отдельно создаёт два ER-вида.
Он заменяет только источники модели БД; после ручных изменений достаточно
экспорта, повторная генерация не требуется.

[build_documents.py](build_documents.py) сохраняет титульник, прежнюю основную часть,
стили и параметры страниц DOCX второго этапа, добавляя architecture.md. Новые страницы модели БД имеют альбомную ориентацию;
исходная часть и остальные страницы остаются книжными.
Он также синхронизирует technical-specification.md.

```text
python -B build_documents.py --out /absolute/path/spec.docx --assets /absolute/path/assets
```

DOCX рендерится штатным render_docx.py с --emit_pdf. После проверки всех страниц
и размещения PDF рядом выполняется:

```text
python -B build_documents.py --out /absolute/path/spec.docx --check
```

Проверка сравнивает все 59 прежних абзацев и 26 ячеек в MD, DOCX и PDF,
положение исходных абзацев в DOCX, 23 идентификатора требований, весь архитектурный
текст и семь рисунков. Отдельно проверяются SHA исходных файлов, стили,
параметры страниц и прочие сохраняемые части OOXML.

[build_presentation.mjs](build_presentation.mjs) использует @oai/artifact-tool из
штатного окружения. CALORICA_ROOT задаёт корень репозитория,
CALORICA_ARTIFACT_WORKSPACE — временную папку, CALORICA_PRESENTATION_SKILL — путь
навыка презентаций, CALORICA_RUNTIME_PYTHON — штатный Python. RUNTIME_NODE,
RUNTIME_NODE_MODULES и RUNTIME_BIN_DIR указывают на штатные зависимости.
Сборщик запускается из build/ временной папки со ссылкой node_modules на штатные
пакеты. CALORICA_OUTPUT_DIR задаёт новую папку результата: финализатор не перезаписывает
проверенный файл. PDF презентации экспортируется из PPTX с сохранением текста.

Для рендера на macOS используется FONTCONFIG_FILE с системными Helvetica Neue
и Times New Roman. Временные превью и отчёты не входят в комплект сдачи.
Поле номера страницы обновляется при открытии Word.
