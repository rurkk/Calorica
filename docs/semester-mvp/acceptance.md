# Приёмка минимальной поставки

Набор проверок семестровой поставки. Пока реализация отсутствует,
все пункты имеют состояние «не проверено».

## Обязательные проверки

| ID | Что предъявить | Способ проверки |
| --- | --- | --- |
| SA-01 | APK устанавливается; регистрация, вход, перезапуск сессии и выход работают | Android + сервер; отозванная сессия больше не принимается |
| SA-02 | Пользователь не читает и не меняет чужие продукты/дневник; сам не получает Admin | Негативные API-тесты с двумя аккаунтами и Admin |
| SA-03 | Базовый каталог и поиск доступны; личная карточка создаётся, редактируется и удаляется | Сквозной Android-сценарий; удалённый продукт не выбирается заново |
| SA-04 | Состав создаётся и редактируется процентами, сохранённые доли не теряют точность | Android: точные 100%, отклонение 90%, повторное сохранение дробных долей |
| SA-05 | Вложенный состав, общий ингредиент по двум путям, конечный ↔ составной работают | Серверные тесты и просмотр актуальных КБЖУ на Android |
| SA-06 | Прямой, косвенный и конкурентно создаваемый цикл запрещены | Интеграционные тесты на PostgreSQL; операция отклонена атомарно |
| SA-07 | Выход NULL, 1, общий и по ингредиентам, переключения и вложенность корректны | Числовые тесты ниже; UI не сбрасывает скрытые коэффициенты |
| SA-08 | Ввод состава граммами нормализуется; массы рецептуры и вычисленный выход не хранятся | API + проверка БД; готовый вес не принимается без исходных масс |
| SA-09 | Порция в дневнике обязательна, редактируется независимо от карточки; дневной итог актуален | Android: создать, изменить, удалить запись; изменить КБЖУ компонента и перечитать историю |
| SA-10 | UTC и локальный день согласованы | Записи около полуночи в двух поясах; выбор прошлой даты; время предзаполнено |
| SA-11 | Оба режима удаления сохраняют историю, каскад направлен к родителям | API-тесты; Admin не каскадирует чужие личные составы; гонка добавления/удаления проверена |
| SA-12 | г/мл конвертируются только при наличии записи конвертации | API: 200 мл при 1,03 г/мл дают 206 г; недоступная единица отклонена |
| SA-13 | Продуктовые лейблы корректны для листьев и составов, удаление убирает связи | API/домен: пересечения, переходы типа, распределение готовых граммов |
| SA-14 | Серверная календарная аналитика и несколько пищевых лейблов корректны | API: полная неделя/месяц с пустыми днями, повторный вклад по лейблам без удвоения общего итога |
| SA-15 | Сетевая ошибка не выглядит как пустой дневник, повторный тап не дублирует запрос | Android: отключение сети; неопределённый результат сохранения не повторяется автоматически |
| SA-16 | Независимые выпуски и развёртывание воспроизводимы | Подписанный APK, точный digest сервера, проверка готовности; docs не запускают релиз |
| SA-17 | Подтверждённые данные переживают перезапуск; резервная копия восстанавливается | Перезапуск и восстановление на отдельной тестовой БД, не поверх пользовательских данных |

### Контрольные числа

- У двух листьев 400 и 80 ккал/100 г, исходные доли по 0,5, коэффициенты 0,5 и 1,5:
  выход 1, блюдо 240 ккал/100 г, порция 200 г — 480 ккал, распределение 50/150 г.
- Если второй коэффициент заменить на NULL: выход 0,75, блюдо 320 ккал/100 г.
- Общий выход 0,8, доли 60/40, порция 200 г: по лейблам 120/80 г, не 250 г сырья.
- Три одинаковые массы сохраняют доли с суммой ровно 1 и повторно редактируются без
  преобразования в 99,99%. Неверные проценты не нормализуются молча.
- 700 ккал только в одном дне выбранной полной недели дают среднее 100 ккал/день.
- Запись 100 ккал с лейблами «завтрак» и «перекус» даёт 100 в каждом разделе,
  но общий итог остаётся 100.

## Минимальные требования к качеству

- HTTPS, серверная авторизация, ограничение частоты auth-запросов, секреты вне Git,
  отсутствие паролей, токенов и содержимого дневника в логах.
- SQL-параметры, decimal-арифметика, валидация конечности/положительности/диапазонов,
  атомарные изменения, откат неуспешных операций и миграции БД.
- Русский интерфейс, читаемые подписи и ошибки, стандартные доступные элементы,
  сенсорные цели не меньше 48 dp. Проверка основного сценария на одном эмуляторе
  и одном доступном физическом Android-устройстве; нижняя граница API 26 сохраняется.
- Нет бесконечной загрузки: запрос ограничен таймаутом, ошибка позволяет повторить
  загрузку.
- Ежедневная резервная копия и копия перед миграцией, хотя бы одна защищённая копия
  вне VPS; конкретное хранилище и доступы определяются до реальных данных.
- Инструкция запуска, настройки секретов, выпуска, восстановления и отката сервера.
  При неудачном деплое не откатывать БД автоматически и не стирать пользовательские данные.

## Минимальная демонстрация

1. Войти, найти базовый продукт, создать личный продукт и вложенный состав.
2. Указать общий выход, добавить съеденную порцию в дневник, показать дневные КБЖУ.
3. Изменить данные ингредиента, перечитать дневник и показать пересчёт.
4. Мягко удалить карточку, показать сохранившуюся историю.
5. Показать результаты API-тестов сложного выхода, циклов и изоляции аккаунтов.
6. Показать APK, сервер и протокол восстановления копии.

Для приёмки фиксируются commit SHA, версии APK/сервера/миграций, результаты и
известные ограничения. Нет реализации или стенда — «не проверено», не «пройдено».
Результат принимается только после SA-01—SA-17; утечка данных, неверные расчёты,
потеря подтверждённых записей и неработающий основной сценарий блокируют сдачу.
