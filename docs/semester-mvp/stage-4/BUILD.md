# Сборка материалов этапа 4

Материалы собраны из редактируемых исходников рядом с этим файлом. PNG в
`screenshots/` являются оригиналами проверки приложения; генераторы их не меняют.

## Презентация

Использован пакет `@oai/artifact-tool` из встроенной среды Codex. Сборщик импортирует
презентацию этапа 3, сохраняет титул, оформление и шрифты, заполняет 12 слайдов
и добавляет заметки из `defense-notes.md`. Таблицы на слайдах 2 и 11 остаются
редактируемыми. Часть полного экрана Android кадрируется в PowerPoint.
Надпись «ИТМО · 2026» на титуле сделана тёмной для контраста с фоном.

Для запуска `build_presentation.mjs` нужны переменные:

| Переменная | Значение |
| --- | --- |
| `CALORICA_ROOT` | Абсолютный путь к репозиторию |
| `CALORICA_ARTIFACT_WORKSPACE` | Отдельная временная папка сборки |
| `CALORICA_PRESENTATION_SKILL` | Папка установленного skill Presentations с `container_tools/` |
| `CALORICA_RUNTIME_PYTHON` | Python встроенной среды Codex |
| `RUNTIME_NODE_MODULES` | Каталог пакетов встроенной среды, содержащий `@oai/artifact-tool` |
| `CALORICA_OUTPUT_DIR` | Новое имя каталога результата внутри временной папки |

Скопировать сборщик во временную папку `build/`, рядом подключить `node_modules`
среды и запустить встроенным Node. Сборщик экспортирует слайды для визуальной
проверки, затем проверяет структуру PPTX, геометрию, шрифты, две нативные таблицы
и повторный импорт Artifact Tool. Итог записывается отдельно от промежуточного PPTX.

## Отчёт

`build_documents.py --out <путь-к-docx>` запускается встроенным Python с
`python-docx`. Источник текста — `implementation-report.md`, шаблон — Word второго
этапа. Сборщик проверяет SHA-256 шаблона, сохраняет стили, нумерацию и колонтитул,
создаёт нативные таблицы и кликабельные ссылки. Отчёт имеет 10 страниц.

Для проверки применяется `render_docx.py` из skill Documents с параметром
`--emit_pdf`. Все страницы результата нужно просмотреть после изменения текста.

## Экспорт и проверка PDF

Использован встроенный headless LibreOffice с отдельным временным профилем.
Для презентации задан локальный `FONTCONFIG_FILE`, включающий системные шрифты
macOS из `/System/Library/Fonts` и `/Library/Fonts`, с временным каталогом кеша.
Без этой настройки встроенный экспорт подменял Helvetica Neue.

В готовом PDF презентации встроены Helvetica Neue и Helvetica Neue Bold,
текст доступен для выделения. Все 12 страниц PDF просмотрены после экспорта.
PDF отчёта совпадает с экземпляром, полученным при проверке Word.

После пересборки необходимо обновить контрольные суммы в `evidence/manifest.json`,
сверить ссылки, числа, изображения и заметки. Версии приложения и результаты
тестов изменяются только при новом фактическом прогоне, а не при пересборке документов.
