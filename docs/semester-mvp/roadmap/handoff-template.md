# Шаблон передачи задачи агенту

Заполнить ID, номер и разрешения. Передача этого текста выполняется отдельно;
наличие карточки в репозитории не запускает работу и не разрешает внешние изменения.

```text
Репозиторий: /Users/raul/ItmoProjects/Calorica
Ты условный агент N, владелец задачи Txx из docs/semester-mvp/roadmap/tasks/Txx.md.
Разработчик: <имя>. Рецензент: <номер из карточки>.

Прочитай корневой CONTRIBUTING.md, README roadmap, workflow.md, agents.md,
свою карточку и её источники.
Работай только в семестровом объёме main. Ветку future/product-development не используй.
Проверь технические зависимости, Git status и владельцев общих файлов до изменений.
Ты не один в репозитории: не отменяй и не перетирай чужие правки.
До реализации прочитай claiming.md, проверь брони на общем origin и подтверди свою
командой task_claim.py claim. Укажи разработчика, уникальный чат и рабочую ветку.
При чужой/неизвестной брони не начинай работу. Если продолжаешь прежний чат,
сверь владельца и сохранённый claim SHA через status, не перезаписывай бронь.
Запиши бронь и статус в tracker.md. Не используй ветку-маркер как рабочую.

Выполни задачу полностью: сначала unit-тесты и RED, затем код и GREEN,
ревью и исправления, интеграция, релиз, отладка выпущенной версии, ручная приёмка.
Для SQL/гонок используй реальные PostgreSQL-проверки, не заменяй их unit-фейками.
Не оставляй отдельную стадию дописывания unit-тестов после реализации.
Новый дефект: сначала регрессионная проверка, затем исправление и новый релиз.

Разрешённые внешние действия: <точно указать push/merge, репозиторий/ветку,
создание/снятие своей ветки-маркера codex/claims/Txx, учебный стенд и выпуск
соответствующего компонента; либо указать «не разрешены»>.
Ограничения: не менять соседние приложения VPS, не удалять пользовательские данные,
не раскрывать секреты и не делать разрушительный откат БД.

Веди свою строку tracker.md. Если нужен общий файл, согласуй с его владельцем.
Перед ручной приёмкой предоставь ссылки и версии APK/backend/схемы, шаги проверки.
Без явного подтверждения человека используй «Ожидает ручной приёмки», не «Готово».
Если нет разрешения, доступа или зависимости, укажи точный блокер; не заявляй релиз.
После получения замечаний продолжи ту же задачу и доведи исправление до повторной приёмки.
Сохраняй бронь во время ревью/релиза/исправлений. Сними её после опубликованной
ручной приёмки или согласованной передачи, используя только свой точный claim SHA.
```

Для T00 релиз приложения не нужен. Для T18 подтверждаются уже выпущенные версии,
а не создаётся новый релиз только из-за изменения отчёта.
