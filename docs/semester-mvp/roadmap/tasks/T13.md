# T13 Продуктовые лейблы и граммы по ним

Агент-владелец: **7**. Рецензент: **агент 2**.
Разработчик: назначается в [трекере](../tracker.md).

## Зависимости и параллельность

- Начало: T11.
- Дополнительные условия живой приёмки: T07.
- Параллельно: P4: с каскадным удалением T14; затем снимает блокировку приёмки T15.
- Требования: SB-04, часть SB-05; SA-13.

Все зависимости обозначают техническую готовность из [workflow](../workflow.md),
не обязательный статус «Готово». Кодовая доставка требует T01 и выполняется
в полном цикле порученной задачи по CONTRIBUTING.md без повторных разрешений;
недостающий доступ — блокер. Владелец не меняет чужие зоны
из [распределения ответственности](../agents.md).

## Что реализовать

- Реализовать общие продуктовые лейблы, Admin CRUD и назначение доступных лейблов своим продуктам.
- Сохранить лейблы при переходе к составному, игнорировать их до возврата к листу; удаление лейбла удаляет его связи.
- Использовать проекцию готовых граммов до листьев общего расчёта агента 2, а не копировать SQL или суммировать сырьевые эквиваленты.
- Разрешить пересечения: вклад листа попадает в каждую его группу; общий вес порции и итог КБЖУ не удваиваются.

## Проверки

- Unit: Admin/владелец, назначение, переходы типа, удаление связей и группировка пересекающихся лейблов.
- PostgreSQL: 200 г при разных выходах распределяются 50/150 г; общий ручной выход 0,8 с долями 60/40 даёт 120/80 г.
- Проверить актуальность после изменения лейбла и сохранённость лейблов родителя без участия в расчёте.

## Критерии приёмки

- Работают реальные API и распределение из дневника; таблицы не служат заменой функции.
- Лейблы родителя не искажают состав; изменение связей отражается при следующем чтении.
- Для Android не добавлены отдельные фильтры/графики, не заявленные scope.md.

## Релиз и отладка

Выпустить backend; передать агенту 3 стабильный интерфейс группировки и проверить его на реальной записи.

Владелец проходит полный цикл из workflow, проверяет выпущенную версию и исправляет
замечания ревью/ручного тестирования до повторного релиза и приёмки. Зелёная
сборка или проверка только на фейках не закрывает задачу.

## Ручная проверка

- Привязать пересекающиеся лейблы листьям, включить их во вложенный состав и запросить распределение.
- Изменить/удалить лейбл и проверить связи, общий итог и изменение группировки.

В tracker.md заносятся результаты проверок, ревью, SHA, версии артефактов, результаты
самостоятельной проверки и явное ручное подтверждение. При дефекте эта карточка
переоткрывается у того же владельца: воспроизведение и исправление,
регрессионная проверка, новый выпуск и повторная приёмка.
