# T10 Android редактор состава и общего выхода

Агент-владелец: **5**. Рецензент: **агент 6**.
Разработчик: назначается в [трекере](../tracker.md).

## Зависимости и параллельность

- Начало: T06.
- Дополнительные условия живой приёмки: T09, T11.
- Параллельно: P3: с T11 и T15; основная форма проверяется с T09, скрытые коэффициенты — после технической готовности T11.
- Требования: SM-04, SM-05, SM-09; SA-04, SA-05, SA-07.

Все зависимости обозначают техническую готовность из [workflow](../workflow.md),
не обязательный статус «Готово». Кодовая доставка требует T01 и разрешения на
внешние изменения; недостающий доступ — блокер. Владелец не меняет чужие зоны
из [распределения ответственности](../agents.md).

## Что реализовать

- Реализовать выбор доступных, в том числе составных компонентов, ввод/правку процентов и повторное открытие точных сохранённых долей.
- Добавить свёрнутую необязательную настройку общего выхода и отображение его источника/эффективного значения.
- При коэффициентах связей общий выход только показывается; правка названия/долей не очищает скрытые серверные настройки.
- Поддержать переходы конечный/составной с запросом недостающих ручных КБЖУ, без нового обязательного ввода масс рецепта.

## Проверки

- Unit: точные проценты, 90/100/110%, сериализация absent/NULL, режим общего выхода и read-only выхода по связям.
- Unit: сохранение скрытых коэффициентов, переход к конечному, ошибки цикла/прав с сервера и отсутствие локальной подмены КБЖУ.

## Критерии приёмки

- Дробные сохранённые проценты не превращаются в 99,99% при открытии и сохранении.
- Сервер остаётся источником расчёта/валидации. Без настройки выход равен 1.
- До закрытия проверен настоящий состав с коэффициентами связей, созданный API T11; фейка для этого недостаточно.

## Релиз и отладка

Выпустить подписанный APK. Живую приёмку скрытых настроек провести на технически готовом T11; это не ожидание его статуса «Готово».

Владелец проходит полный цикл из workflow, проверяет выпущенную версию и исправляет
замечания ревью/ручного тестирования до повторного релиза и приёмки. Зелёная
сборка или проверка только на фейках не закрывает задачу.

## Ручная проверка

- Создать и изменить вложенное блюдо процентами, настроить общий выход и сверить показанные КБЖУ с ответом API.
- Через API задать коэффициент ингредиента, открыть карточку в APK, изменить название/доли и убедиться, что коэффициент не потерян.

В tracker.md заносятся результаты проверок, ревью, SHA, версии артефактов, результаты
самостоятельной проверки и явное ручное подтверждение. При дефекте эта карточка
переоткрывается у того же владельца: воспроизведение и исправление,
регрессионная проверка, новый выпуск и повторная приёмка.
