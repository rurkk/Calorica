# T12 Единицы и конвертация порции на сервере

Агент-владелец: **7**. Рецензент: **агент 3**.
Разработчик: назначается в [трекере](../tracker.md).

## Зависимости и параллельность

- Начало: T05.
- Дополнительные условия живой приёмки: T07.
- Параллельно: P2: с T07 и T09; свои миграции и выделенные units-пакеты.
- Требования: SB-03; SN-03; SA-12.

Все зависимости обозначают техническую готовность из [workflow](../workflow.md),
не обязательный статус «Готово». Кодовая доставка требует T01. Перед слиянием
проверенного PR агент спрашивает «Вливаем ли всё в main?». После согласия доводит
CI/CD, нужный деплой и проверки до закрытия без второго подтверждения приёмки;
недостающий доступ — блокер. Владелец не меняет чужие зоны
из [распределения ответственности](../agents.md).

## Что реализовать

- Создать справочник грамм/миллилитр и конвертации конкретного продукта в граммы.
- Граммы доступны всегда; миллилитры — только при заданной конвертации. Личный продукт изначально поддерживает только граммы.
- Предоставить каталоговый интерфейс конвертации для дневника; агент 3 подключает его через согласованный контракт.
- После конвертации сохранять в дневнике только граммы с округлением до 3 знаков; выход блюда не является коэффициентом единиц.

## Проверки

- Unit: допустимая единица, положительность/конечность и точность, отсутствие конвертации, нулевой результат после округления.
- Интеграция: 200 мл при 1,03 г/мл дают 206 г, исходная единица не сохраняется, чужой продукт недоступен.

## Критерии приёмки

- Неподдерживаемая единица отклоняется; коэффициент не подменяется предполагаемой плотностью.
- Конвертация работает через опубликованный diary API, не только отдельную функцию.
- Новый выбор единиц в Android не добавляется: интерфейс семестра вводит граммы.

## Релиз и отладка

Выпустить backend с миграцией единиц и интеграцией в дневник; потребляющую правку diary согласовать с агентом 3.

После согласия на слияние владелец проходит полный цикл из workflow, проверяет
выпущенную версию и исправляет замечания до успешного результата. Затем закрывает
задачу без второго подтверждения приёмки; одна зелёная сборка или фейки не заменяют
невыполненные критерии, нужный деплой и проверку доставленной версии.

## Ручная проверка

- Создать доступную базовую конвертацию и записать 200 мл через API; перечитать 206 г.
- Попытаться использовать мл без конвертации, в том числе у нового личного продукта; проверить отказ и отсутствие записи.

В tracker.md заносятся результаты проверок, ревью, SHA, версии артефактов, результаты
самостоятельной проверки, согласие разработчика на слияние и итоги CI/CD/деплоя.
При дефекте эта карточка
переоткрывается у того же владельца: воспроизведение и исправление,
регрессионная проверка, нужный новый выпуск и повторная проверка результата.
