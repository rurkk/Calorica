# T06 Android каталог и личные продукты

Агент-владелец: **5**. Рецензент: **агент 4**.
Разработчик: назначается в [трекере](../tracker.md).

## Зависимости и параллельность

- Начало: T02.
- Дополнительные условия живой приёмки: T04, T05.
- Параллельно: P2: с Android auth T04 и дневником T08; общие файлы интегрирует агент 4.
- Требования: SM-02, SM-03, SM-09; SA-03, SA-15.

Все зависимости обозначают техническую готовность из [workflow](../workflow.md),
не обязательный статус «Готово». Кодовая доставка требует T01. Перед слиянием
проверенного PR агент спрашивает «Вливаем ли всё в main?». После согласия доводит
CI/CD, нужный деплой и проверки до закрытия без второго подтверждения приёмки;
недостающий доступ — блокер. Владелец не меняет чужие зоны
из [распределения ответственности](../agents.md).

## Что реализовать

- Реализовать список базовых/своих продуктов, поиск и карточку с КБЖУ на 100 г.
- Добавить создание и изменение личного конечного продукта и мягкое удаление с сохранением в составах.
- Базовые карточки в Android просматриваются; серверное администрирование не превращается в дополнительный экран.
- Предоставить согласованный выбор продукта для дневника и состава; после мутаций перечитывать данные.

## Проверки

- Unit: ввод КБЖУ, состояния списка/поиска, отмена устаревшего ответа, доступность личных действий и обновление после записи.
- Проверить, что UI не рассчитывает собственные КБЖУ и не отправляет скрытые значения как NULL.

## Критерии приёмки

- Реальные данные приходят из T05; чужой личный продукт не появляется при смене аккаунта.
- Ввод, поиск, сохранение и удаление имеют понятные состояния; двойной тап не создаёт повторный запрос.
- Выбор продукта доступен потребителям без дублирования каталога.

## Релиз и отладка

Выпустить подписанный APK; проверить каталог на опубликованном backend и сценарий выбора для дневника.

После согласия на слияние владелец проходит полный цикл из workflow, проверяет
выпущенную версию и исправляет замечания до успешного результата. Затем закрывает
задачу без второго подтверждения приёмки; одна зелёная сборка или фейки не заменяют
невыполненные критерии, нужный деплой и проверку доставленной версии.

## Ручная проверка

- Войти, найти базовый продукт, создать/изменить/удалить личный; повторно открыть список.
- Изменить аккаунт и отключить сеть во время поиска/сохранения; проверить сообщение и повтор чтения.

В tracker.md заносятся результаты проверок, ревью, SHA, версии артефактов, результаты
самостоятельной проверки, согласие разработчика на слияние и итоги CI/CD/деплоя.
При дефекте эта карточка
переоткрывается у того же владельца: воспроизведение и исправление,
регрессионная проверка, нужный новый выпуск и повторная проверка результата.
