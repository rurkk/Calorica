# Трекер реализации

Рабочее состояние [roadmap](README.md). Условные агенты назначены; разработчиков
команда вписывает перед стартом. Это исходный список, не отчёт о выполненной реализации.
Правила статусов и завершения — в [workflow](workflow.md).

## Назначения и состояние

Активный владелец определяется [общей бронью на origin](claiming.md);
таблица отражает назначение и стадию выполнения. Перед стартом проверить оба источника:
бронь может появиться раньше обновления main. Один человек может последовательно
вести несколько номеров; при передаче задачи обновить строку и общую бронь.
Условный агент и рецензент заданы в карточке. Для изменения зоны ответственности
согласовать также [agents.md](agents.md).

«Технически готово» отмечается отдельно от «Готово»: потребитель может использовать
проверенный контракт и реализацию до завершения ручной приёмки всей задачи.
Для живого API/APK необходим опубликованный и проверенный артефакт.
У всех кодовых задач доставка дополнительно зависит от T01.

При начале работы скопировать блок ниже под отдельный заголовок Txx.
Ссылки относятся к точному SHA и версии: подтверждения старой версии после
изменения затронутого поведения требуют повторной проверки.


Неприменимую часть отметить «не применимо» и объяснить, например отсутствие
релиза приложения у T00. Незапущенную проверку пометить «не выполнена» с причиной.
При отсутствии ручного подтверждения человека статус остаётся
«Ожидает ручной приёмки». Секреты и пользовательские данные в отчёт не помещаются.

а не отсутствие ошибок в реализации.

Для нового замечания добавить строку и подробные шаги под ней: ожидаемый/фактический
результат, APK/backend/схема, сеть и часовой пояс при необходимости.
