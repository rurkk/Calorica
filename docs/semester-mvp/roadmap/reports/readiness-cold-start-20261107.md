# Readiness после холодного запуска — 7 ноября 2026

Первичный ответ HTTP503 `OUT_OF_SERVICE` из PR47 повторно исследован по
runtime-логам Render, состоянию Neon и живому API. **Текущая недоступность не
подтвердилась: приложение завершило холодный запуск и отвечает HTTP200 `UP`.**
Перезапуск, новый деплой, изменение тарифа, конфигурации и данных для восстановления
не потребовались. Этот отчёт исправляет классификацию временного ответа в трекере;
он не заявляет исправление кода backend или устранение засыпания Render Free.

`ef348ac827182ba213fc545443529145ae6868b4`, deploy
`dep-dbmdavd9fdbs73clp1cg`, Free, Git-backed Docker, автодеплой выключен.

В backend readiness включает `readinessState`, `db` и `schema`. После запуска
Tomcat `AuthInitialization` выполняется как `ApplicationRunner`: до завершения
инициализации Boot ещё не принимает API-трафик. Поведение REFUSING_TRAFFIC,
liveness200, readiness503 и отказ auth без записи до завершения инициализации
уже покрыто `AccountsIntegrationTest` (существующий тест, в этой диагностике
заново не запускался). Строка `Started ...Application` сама по себе не означает
окончания всех runners. В диагностическом окне ошибок подключения к БД,
неприменённых миграций или падения процесса не обнаружено.

Neon API подтвердил основную compute `ep-morning-grass-barfhgst` в состоянии
`active`, `disabled=false`, 0.25 CU. Другие ветки не менялись. Производственные
данные не выгружались, SQL-мутации и восстановление БД не выполнялись.

## Дальнейшая эксплуатация

При первом обращении после сна следует дождаться конечного результата запуска:
ранний `OUT_OF_SERVICE` при продолжающемся старте нельзя сразу объявлять
постоянной недоступностью. В этом случае JVM и Spring потребовали около двух минут,
затем завершилась инициализация auth. Android ждёт readiness до 90 секунд;
при более долгом пробуждении может потребоваться кнопка повторной попытки.
Это оставшееся ограничение времени ожидания на бесплатном стенде; его изменение
и новый Android-релиз в этой диагностике не выполнялись.

Для ручной диагностики проверяются логи текущего запуска, отдельно liveness и
readiness, затем чтение API. Постоянные внешние пинги для удержания сервиса
активным не настраивались. Тарифы и ресурсные лимиты не менялись.

Активная отметка о readiness-инциденте в roadmap и tracker снята. Блокировка
GitHub Actions, физический Android, совместимый опубликованный rollback и
полнота приёмки карточек этим результатом не закрываются. Владельцы и брони сохранены.
