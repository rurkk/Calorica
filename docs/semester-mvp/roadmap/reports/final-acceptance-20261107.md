## Сеть и минимальная демонстрация

TLS CONNECT relay на localhost пропускает исходный HTTPS без расшифровки и без
замены сертификата. Для одного сохранения удержаны только серверные зашифрованные
пакеты после отправки запроса. Независимый API GET подтвердил **ровно одну новую
запись 111 г** при двух быстрых тапах. APK по таймауту показал «Результат сохранения
неизвестен», перечитал фактически сохранённую строку, оставил запрет записи до
«Записи проверены». Более поздний GET подтвердил отсутствие delayed replay.
[Результат](evidence/final-ui-fault-20261107.json),
[безопасные TLS-счётчики](evidence/final-tls-relay-20261107.jsonl).

Через `svc wifi/data disable` сеть эмулятора отключалась полностью.
Чтение показало явную сетевую ошибку и **не** пустой дневник. После включения
сети и ручного «Обновить» тот же дневник восстановлен. Сохранение новой порции
при отключённой сети также завершилось ограниченной неоднозначной ошибкой;
серверный GET подтвердил отсутствие строки. После восстановления сети пустой
день перечитан, пройдено «Записи проверены», автоматического повтора не было.
Только затем вручную создана новая порция.

Через signed UI создан **новый вложенный состав**: UIFinal One (100% листа)
включён как 100% ингредиент нового состава; задан общий выход **0.8**.
API-расчёт показан в APK: **312.5 ккал/100 г**, съеденная порция **80 г → 250 ккал**.
После изменения своего листа **250 → 400** история в APK перечитана и показала
**400 ккал**. Своя карточка мягко удалена через UI с подтверждением диалога.

Серверный auth-негатив дополнительно исполнен на отдельной технической сессии:
попытка регистрации с role=ADMIN → 400, logout → 204, старый access → 401,
refresh отозванной сессии → 401. Пользовательские роли не менялись.

Проверка истории после soft-delete в APK: баннер «Продукт удалён из каталога;
запись сохранена», **80 г / 400 ккал** остались. Удаление этой записи через APK
вернуло пустой день и нулевой итог. Через редактор APK выполнены оба перехода
LEAF → COMPOSITE → LEAF, исходные ручные **120 ккал** сохранились.
При отключении сети во время поиска показана ошибка, ручной повтор после
восстановления сети вернул каталог.

Точный fingerprint эмулятора:

В crash-buffer обнаружены две ошибки **UiAutomationService already registered**

## Сессии и изоляция signed UI

Lost committed refresh проверен на неизменённом release APK через TLS relay:
readiness пропущен, следующий зашифрованный ответ удержан. READ ONLY число
refresh-записей **только своего нового технического аккаунта** выросло ровно на 1.
APK вернулся к «Войти в аккаунт» с сообщением «Не удалось безопасно восстановить
сессию». Повторный process kill/start не сделал нового refresh: приращение 0.
Хеши токенов не читались/не экспортировались.
[Отдельное доказательство](evidence/final-refresh-fault-20261107.json).

В signed UI выполнены logout → вход прежним техническим аккаунтом → поиск:
личные UIFinal другого аккаунта не показаны. Logout → вход новым UI-аккаунтом
вернул его данные. Offline-правка имени продукта привела к uncertainty,
заблокированным полям и «Перечитать данные»; независимый API подтвердил исходное
имя и отсутствие повтора. После сети и перечитывания пользователь вышел.
Измерены 8 полностью видимых clickable targets на density 180 dpi:
высота каждой **54 px = 48 dp**, ширина 74–178 px, все не меньше 48 dp.
Это выборочная фактическая проверка стандартных компонентов, не заявление
об исчерпывающем accessibility-аудите всех размеров экранов.

## Очистка и эксплуатационный итог прогона

удаление составной карточки.

Технические аккаунты остаются, как допускает API; активных тестовых карточек
этого прогона не оставлено. Известные API-сессии и текущая signed UI-сессия

Пользователь ответил, что подготовит Admin-аккаунт сам. До получения готового

## Дополнительная проверка старта signed0.1.5

На том же собственном AVD после reboot обнаружились сохранённые canonical
proxy-ключи Android от fault relay. Первоначальный сброс только `http_proxy`
не очистил proxy-кэш ConnectivityService; два диагностических retry-прогона
**не прошли и не засчитываются**. Полный reset canonical keys, обработка
legacy `:0` и reboot восстановили прямую сеть; контрольный запуск signed APK
дошёл до входа. Это дефект настройки проверочного стенда, не исправление APK.

На чистой настройке повторён весь сценарий: offline startup → ограниченная
ошибка через **91.47 с** → включение сети → **один** ручной retry → экран входа
через **4.57 с**. Результат PASS; приложение не менялось. AVD после этого
остановлен, proxy host пустой/port0; тестовый relay не работает.
