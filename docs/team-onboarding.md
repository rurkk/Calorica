# Быстрый старт разработчика и агента

Репозиторий: [rurkk/Calorica](https://github.com/rurkk/Calorica).
Порядок выбора и выполнения задачи — [CONTRIBUTING.md](../CONTRIBUTING.md).
Адреса, права и команды инфраструктуры — [deploy/access/README.md](../deploy/access/README.md).
Установка инструментов, запуск на телефоне и поиск ошибок — [краткая инструкция по отладке](debugging.md).

## Что получить от владельца

- Общий закрытый архив `calorica-team-admin.zip`: одинаковый для всех участников.
  В нём `.env.infra`, инструкция подключения и действующие API/SQL-секреты.
- Приглашение GitHub в коллабораторы с правом записи: оно нужно для общей брони,
  push рабочей ветки и PR. Общий инфраструктурный архив не содержит GitHub-токена.
- Личные приглашения Neon Admin и Better Stack Member для веб-панелей.
  Общие API/MCP-ключи работают также до принятия этих приглашений.

Архив передаётся по закрытому каналу. В репозитории опубликованы инструкции
и настройки, а не сами секреты. Не вставляйте `.env.infra` в сообщение агенту;
передайте ему путь к файлу в рабочей копии.

## Первый запуск

1. Принять GitHub-приглашение. Войти на компьютере в свой GitHub-аккаунт.
   При HTTPS и установленном GitHub CLI: `gh auth login`, затем `gh auth setup-git`.
   При использовании SSH настройте личный SSH-ключ GitHub.
2. Клонировать актуальный `main`, проверить `git remote -v`:

   ```sh
   git clone https://github.com/rurkk/Calorica.git
   cd Calorica
   ```

3. Скопировать `.env.infra` из общего архива в корень клона. На macOS/Linux:
   `chmod 600 .env.infra`. Файл исключён из Git.
4. Убедиться, что настроены свои Git `user.name` и `user.email`: скрипт бронирования
   создаёт коммит-маркер. При необходимости задать их локально через `git config`.
5. Нужны Git и Python 3.9+. Для SQL через psql — клиент PostgreSQL 17+;
   для backend — JDK 21. Остальное окружение устанавливается под выбранный компонент
   по [корневому README](../README.md) и [инструкции backend](../backend/README.md).
6. При установленном Codex CLI запустить агента из корня:

   ```sh
   python3 scripts/infra/access.py codex
   ```

   Команда передаст три MCP-подключения и общие ключи через окружение.
   Для Codex Desktop откройте доверенный проект Calorica и начните новый сеанс
   после копирования профиля. Другой локальный агент с терминалом может пользоваться
   `scripts/infra/access.py` без MCP.

При отдельном worktree нужен доступ к тому же профилю: скопировать его в корень
этого worktree с правами 600 либо передавать исходный абсолютный путь через
`python3 scripts/infra/access.py --env-file /private/path/.env.infra <команда>`.
Облачный агент без локального файла потребует отдельно настроенных закрытых секретов.

## Промпт для первого диалога

Замените имя и GitHub-логин. Сначала агент помогает выбрать задачу;
до выбора он не создаёт бронь и не начинает реализацию.

```text
Я <имя / GitHub-логин>, работаем в репозитории rurkk/Calorica.
Прочитай AGENTS.md, CONTRIBUTING.md, docs/team-onboarding.md,
docs/semester-mvp/roadmap/README.md, tracker.md и claiming.md из этой папки.

Общий .env.infra лежит в корне. Проверь доступы через MCP CaloricaNeon,
CaloricaRender, CaloricaLogs или scripts/infra/access.py. Секреты не выводи.
Проверь origin, GitHub-авторизацию, актуальные брони и зависимости.
Предложи 2–3 свободные задачи, которые можно начать сейчас, и дождись моего выбора.
Если доступна одна задача — предложи одну; при блокере объясни причину.

После выбора забронируй задачу через task_claim.py с моим именем и уникальным
ID чата, создай отдельную ветку codex/ и обновляй tracker.md.
Доведи работу по CONTRIBUTING: реализация, необходимые тесты, проверки, ревью,
исправления и отладка. Общую БД используй для просмотра; изменения отлаживай
в dev-ветке. Чужие правки не перетирай, платные ресурсы не включай.

Разрешаю создание своей брони, push своей рабочей ветки и PR в rurkk/Calorica.
Снятие своей брони — по правилам claiming.md после приёмки/согласованной передачи.
Merge в main и выпуск на общий стенд — после отдельного моего подтверждения.
```

## Как понять, что можно начинать

- GitHub-аккаунт принят в коллабораторы и имеет право записи; одного публичного
  чтения репозитория недостаточно для `claim` и push.
- `python3 scripts/roadmap/task_claim.py status` успешно читает общий origin.
  Пустой список означает отсутствие текущих броней, а не готовность всех задач:
  агент также проверяет tracker и технические зависимости.
- Проверки инфраструктуры работают через общий профиль; невозможность подключиться
  не заменяется утверждением, что всё настроено.
- Выбранная задача подтверждена человеком; `claim` завершился успешно, SHA брони
  сохранён в tracker. Только после этого начинается код и тесты задачи.

Рабочая ветка и ветка-маркер `codex/claims/Txx` имеют разное назначение.
Общий доступ к инфраструктуре не отменяет владельцев задач, бронь и ручную приёмку.
