# Аутентификация и роли

## Функциональные требования

- **FR-AUTH-01. Регистрация.** Пользователь может создать аккаунт по уникальному e-mail
  и паролю.
- **FR-AUTH-02. Вход и выход.** Пользователь может войти в созданный аккаунт и выйти из
  него.
- **FR-AUTH-03. Минимальный профиль.** Регистрация не требует имени, возраста, роста,
  веса, пола, уровня активности или цели. В профиле доступны только e-mail и
  необязательные дневные ориентиры по калориям, белкам, жирам и углеводам.
  При регистрации ориентиры остаются незаполненными: значения по умолчанию не
  подставляются, поля ориентиров на экране регистрации не предлагаются. Уже
  зарегистрированный пользователь может открыть профиль и самостоятельно задать или
  изменить любой из ориентиров. Заполнение каждого ориентира добровольное.
- **FR-AUTH-04. Авторизация на сервере.** Сервер проверяет личность пользователя и права
  доступа при каждом защищённом действии. Скрытие действий в мобильном интерфейсе не
  заменяет серверную проверку.
- **FR-ROLE-01. Роль пользователя.** Обычный пользователь видит и изменяет только свои
  дневник, профиль, ориентиры и личные продукты.
- **FR-ROLE-02. Роль Admin.** Admin дополнительно управляет базовым каталогом и общими
  продуктовыми лейблами в том же мобильном приложении. Он не получает доступ к личным
  продуктам, дневникам, профилям или аналитике других пользователей.
- **FR-ROLE-03. Выдача ролей.** Новая учётная запись получает роль обычного
  пользователя. Обычный пользователь не может получить роль `Admin` через интерфейс или
  публичное API.

## Не входит в MVP

- подтверждение e-mail;
- смена и восстановление пароля;
- вход через Google;
- передача персональных данных между пользователями.
