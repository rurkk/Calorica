# Безопасность и изоляция данных

Требования проверяются на двух обычных аккаунтах и Admin. Отсутствие кнопки в UI
не является доказательством защиты. Проверки выполняются прямыми запросами к API.

| ID | Требование | Проверка |
| --- | --- | --- |
| NFR-SEC-01 | Любое чтение/изменение личных данных проверяет владельца на сервере; Admin не читает чужой дневник, профиль и продукты | Подмена ID в карточке, составе, дневнике, профиле, поиске и аналитике; ответ не содержит чужих данных |
| NFR-SEC-02 | Регистрация выдаёт только обычную роль; роль и owner ID из тела запроса не позволяют повысить доступ | Попытки mass assignment; невозможность изменения базового каталога обычным пользователем |
| NFR-SEC-03 | Внешнее API только HTTPS; БД недоступна из интернета; секреты отсутствуют в Git и APK | Проверка конфигурации портов/TLS, репозитория и сборки; соединение с БД извне отклоняется |
| NFR-SEC-04 | Пароли только в виде Argon2id-хешей с индивидуальной солью, не в открытом/обратимо зашифрованном виде | Проверка БД и конфигурации encoder; параметры не ниже принятой OWASP-базы и замер на сервере |
| NFR-SEC-05 | Access JWT — 15 минут; абсолютный срок сессии 30 дней; refresh ротируется атомарно, в БД только хеши | Истечение сроков с управляемыми часами, повторный refresh, одновременное обновление и отзыв сессии |
| NFR-SEC-06 | После успешного logout сервер отклоняет следующие запросы с токенами этой сессии; другие сессии сохраняются | Запрос старым access/refresh после logout, повторный вход; незавершённый до logout запрос не считается новым |
| NFR-SEC-07 | Refresh защищён Android Keystore и исключён из backup; выход/смена аккаунта очищает пользовательские данные клиента | Проверка хранения и резервного копирования, сценарий A → logout → B без отображения данных A |
| NFR-SEC-08 | Ограничены попытки входа/регистрации/refresh; сообщение о неверном входе не различает отсутствующий email и неверный пароль | Для входа: после 10 неудач за 15 мин на сочетание IP+email следующие попытки ограничены до конца окна; также 100 попыток/IP за 15 мин. Регистрация: 5/IP/час, refresh: 60/сессию/мин; 429 и Retry-After. Значения конфигурируемы, без бессрочной блокировки аккаунта |
| NFR-SEC-09 | SQL параметризован; сервер проверяет диапазоны, суммы долей, числа, ссылки и отсутствие циклов независимо от клиента | Невалидные JSON, SQL-метасимволы, NaN/Infinity, чужие связи и циклы не повреждают данные; внутренние SQL/stack trace не выдаются клиенту |
| NFR-SEC-10 | При запрете каскадного удаления базового продукта Admin не получает названий или владельцев чужих составов | Ответ содержит только основание недоступности режима, без списка чужих сущностей |

Сроки токенов и rate limits — проектные значения по умолчанию. Ограничение по IP
должно учитывать только доверенный reverse proxy, не произвольный X-Forwarded-For.
До реализации выбирается единый механизм ограничения, не обходящийся перезапуском
отдельного обработчика или сменой его экземпляра.

Источники технических правил и подробности:
[политика сессий](../../architecture/runtime-policies.md),
[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html),
[OWASP OAuth2](https://cheatsheetseries.owasp.org/cheatsheets/OAuth2_Cheat_Sheet.html).
Это инженерные требования, не заявление о юридической сертификации или соответствии
законодательству о персональных данных. Правовые условия публичного запуска проверяются отдельно.
