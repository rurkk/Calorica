# Права доступа и мягкое удаление

## Изоляция данных

Обычный пользователь работает только с собственными данными и общим базовым каталогом.
Его личные продукты, составы, дневник, ориентиры и аналитика недоступны другим
пользователям и Admin.

## Мягкое удаление продуктов

Продукт удаляется мягко через признак `isDeleted`.

- Личный продукт может удалить только его владелец.
- Базовый продукт может удалить только Admin.
- Мягко удалённый продукт скрывается из актуального каталога и не доступен для новых
  записей дневника.
- Сам объект сохраняется в базе, поэтому существующие связи и расчёты не теряют
  исходный продукт.
- При любом режиме удаления продукта, включая каскадный, связанные записи дневника
  сохраняются и продолжают учитываться в исторической аналитике. Удаление карточки
  продукта или зависимого состава не удаляет факты питания.

## Режимы удаления

При удалении продукта пользователь выбирает один из режимов.

1. **Сохранить в составах.** Продукт остаётся компонентом существующих составов и
   продолжает участвовать в их расчёте, но не может быть выбран для нового добавления.
2. **Каскадно удалить зависимые составы.** Вместе с продуктом мягко удаляются все
   составные продукты, которые прямо или косвенно от него зависят. Дочерние компоненты
   удаляемого продукта не удаляются.

Перед каскадным удалением интерфейс показывает список затрагиваемых составных продуктов
и запрашивает подтверждение.

Если Admin удаляет базовый продукт и среди зависимых составов есть личные продукты
других пользователей, каскадное удаление недоступно. В таком случае разрешён только
режим «сохранить в составах»: это исключает скрытое изменение личных данных и не
раскрывает их администратору.
