# analytics

`GET /api/v1/analytics?date=YYYY-MM-DD&zone=IANA&period=DAY|WEEK|MONTH`
возвращает полный локальный день, неделю пн–вс либо календарный месяц. `days`
содержит все даты, в том числе пустые; среднее делится на `dayCount`, а не число
заполненных дней или количество прошедших часов. UTC-границы полуоткрытые и
получаются из календаря IANA, включая DST и пропущенные даты.

`AnalyticsService` держит один read-only REPEATABLE READ `CatalogSnapshot` для
всех частей ответа. `DiaryAnalyticsRead` читает только дневник владельца и
использует существующие catalog calculation / diary SQL portion scaling.
`AnalyticsRepository` агрегирует готовые значения в PostgreSQL NUMERIC без
промежуточного округления и без чтения таблиц каталога. Группы пищевых лейблов
расширяются после формирования общего итога, поэтому пересечения не удваивают его.
Ответ с более чем 10000 записями за период либо превышением числовых лимитов
отклоняется целиком; сводки в БД не сохраняются.

Продуктовые группы приходят через публичный
`catalog.application.labels.ProductLabelRead.distribution(actor, portions, snapshot)`.
Реализация этого порта в T13 использует общий `allocateLeaves` и присоединяет
продуктовые лейблы после раскрытия графа. Родительские лейблы не участвуют,
пересечения повторяют готовые граммы в каждой группе. Изменение состава, выхода,
КБЖУ и лейблов пересчитывает прошлые периоды; мягкое удаление сохраняет историю.
Интеграционные тесты аналитики используют реальный порт и production changelog.
